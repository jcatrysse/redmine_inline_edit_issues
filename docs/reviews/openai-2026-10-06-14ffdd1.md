Major, app/controllers/inline_issues_controller.rb:78-110 (update_multiple loop)
The code deletes start_date, due_date and done_ratio from every submitted issue whenever the corresponding “parent issues derived” setting is enabled, instead of only doing so for parent issues. With Setting.parent_issue_dates = 'derived' or Setting.parent_issue_done_ratio = 'derived', leaf issues’ dates and % done remain editable in Redmine, but here the attributes are dropped unconditionally and silently ignored.
Scenario: Set Administration > Settings > Issue tracking > “Calculate the due date of parent issues” (and/or “Calculate the done ratio of parent issues”) to “derived”. On the inline edit form, a manager changes start_date, due_date or done_ratio of a leaf issue and submits. The page shows “Successful update.”, but the dates/% done of the leaf issue do not change because the attributes were removed from attribute_hash before safe_attributes=.
Fix: Apply the deletions only for parent issues. For example:
- unless allow_edit_dates || issue.leaf?
    attribute_hash.delete('start_date')
    attribute_hash.delete('due_date')
  end
- unless allow_edit_done_ratio || issue.leaf?
    attribute_hash.delete('done_ratio')
  end
Alternatively, use an explicit predicate reflecting Redmine’s behaviour (eg. issue.leaf? or issue.children.any?) so that only parent issues are affected.

Resolution: not a defect. The deletions sit inside `if issue.children.any?` (the branch for
parent issues; the `else` branch keeps every attribute), so leaf issues keep their dates and %
done. Shown in the browser: docs/e2e/edit-form-manager.png (leaf issues have date and % done
inputs, the parent shows text) and the core default settings used there are "derived".

Major, test/functional/inline_issues_controller_test.rb:6 and test/integration/context_menu_test.rb:6
Unqualified reference to INLINE_EDIT_FIXTURES relies on include to bring in a module constant. Including a module does not make its constants available as unqualified names; Ruby resolves constants by lexical scope first and does not import constants from included modules. This can raise NameError: uninitialized constant INLINE_EDIT_FIXTURES when the class is loaded.
Concrete failure: Running the test suite on Ruby 3.3 may abort at class definition time with NameError for InlineIssuesControllerTest and InlineEditContextMenuTest because INLINE_EDIT_FIXTURES is not defined in those classes’ lexical scope.
Fix: Refer to the constant with its fully-qualified name or define a top-level alias. For example:
- Change fixtures(*INLINE_EDIT_FIXTURES) to fixtures(*RedmineInlineEditIssues::TestHelper::INLINE_EDIT_FIXTURES) in both files; or
- In test/test_helper.rb, add INLINE_EDIT_FIXTURES = RedmineInlineEditIssues::TestHelper::INLINE_EDIT_FIXTURES at top level so tests can reference INLINE_EDIT_FIXTURES unqualified.

Resolution: not a defect. Ruby looks a constant up in the lexical scope and then in the ancestors
of the class, which include the included module, so INLINE_EDIT_FIXTURES resolves. Both test
classes load and run on Ruby 3.3.6 and 3.2.6 (42 and 41 runs green in this session).
